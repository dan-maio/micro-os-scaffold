complete because the test is written against its interface; the port keeps
only the files its build and runner need; the test harness and scripts
keep only the selected test and the material it references.

The workspace is self-contained and relocatable: the scripts find it from
their own location. [Adding new functionality](#adding-new-functionality-to-this-workspace)
explains where new files, libraries and tests go.

## Build


## Run the test

```bash
./test.sh aarch64-rpi-zero-2w-cmake-gcc-debug smp-mat-test
```

`test.sh` configures and builds first, then runs the CTest cases of the
named test (a test directory name or a selection id). Without a name it
runs the selected tests. Hardware (`-hwd`) cases need the board and the
probe; add `--hwd` to include them when a test also has another image,
or `--hwd-only` to run nothing but the hardware case.

## Added in this workspace: Wi-Fi tests

## Adding new functionality to this workspace

Everything is compiled from source: the kernel (`micro-os-plus-iii-smp/`) and the port
(`micro-os-plus-iii-aarch64/`) export CMake INTERFACE targets, and the test executable compiles
their sources together with its own. There is no library to rebuild or install;
after any change run `./build.sh` (or `./test.sh`, which builds first).

### Which file picks up what

| You add | Put it in | Picked up by | Edit a CMake file? |
| --- | --- | --- | --- |
| `.cpp` of the test | `micro-os-plus-iii-aarch64/test/rpi-zero-2w/smp-mat-test/` | `test/CMakeLists.txt` globs `<app>/*.cpp` | no |
| header of the test | the same directory | the directory is on the include path | no |
| `.c` / `.S` of the test | the same directory | not globbed | `board_test_sources()` in `test/rpi-zero-2w/tests.cmake` |
| code shared by all tests of the board | `micro-os-plus-iii-aarch64/test/rpi-zero-2w/src/*.cpp`, `include/` | globbed, on the include path | no |
| board code (driver, start-up) | `micro-os-plus-iii-aarch64/test/boards/rpi-zero-2w/src/` | `micro-os-plus-iii-aarch64/CMakeLists.txt` globs `*.cpp`, `*.S` | no |
| board glue used by some tests only | `micro-os-plus-iii-aarch64/test/boards/rpi-zero-2w/glue/` | named, never globbed | `board.cmake` variable + `board_test_sources()` |
| port source | `micro-os-plus-iii-aarch64/src/` | explicit list | `target_sources (micro-os-plus-iii-aarch64-interface ...)` in `micro-os-plus-iii-aarch64/CMakeLists.txt` |
| kernel source | `micro-os-plus-iii-smp/src/` | explicit list | `target_sources (micro-os-plus-iii-interface ...)` in `micro-os-plus-iii-smp/CMakeLists.txt` |
| a library | anywhere in the workspace | an INTERFACE or STATIC target | `board_test_libs()` in `tests.cmake` |
| a new test | `micro-os-plus-iii-aarch64/test/rpi-zero-2w/<name>/` | globbed: one executable and one CTest case per directory | only for non-default settings |

The globs use `CONFIGURE_DEPENDS`, and `build.sh` re-runs CMake every time, so
a new file or directory is noticed without removing the build tree.

### 1. Add a source file to the test

```bash
cd micro-os-plus-iii-aarch64/test/rpi-zero-2w/smp-mat-test
$EDITOR filter.cpp filter.hpp          # #include "filter.hpp" from main.cpp
cd ../../../../tests && ./build.sh
```

A C or assembly file is not globbed. Name it in the board's
`micro-os-plus-iii-aarch64/test/rpi-zero-2w/tests.cmake`:

```cmake
function (board_test_sources _app _out)
  if (_app STREQUAL "smp-mat-test")
    set (${_out} "${CMAKE_CURRENT_FUNCTION_LIST_DIR}/smp-mat-test/fast-math.c" PARENT_SCOPE)
  else ()
    set (${_out} "" PARENT_SCOPE)
  endif ()
endfunction ()
```

Code that several tests of this board use goes to
`micro-os-plus-iii-aarch64/test/rpi-zero-2w/src/` (sources) and `micro-os-plus-iii-aarch64/test/rpi-zero-2w/include/`
(headers); both are compiled into every test of the board.

### 2. Per-test build settings

`micro-os-plus-iii-aarch64/test/rpi-zero-2w/tests.cmake` is included by `micro-os-plus-iii-aarch64/test/CMakeLists.txt`
and holds everything a directory listing cannot express. Each hook receives the
test name in `_app` and returns a list in `_out`:

| Hook or list | Purpose |
| --- | --- |
| `board_test_defines (_app _out)` | extra compile definitions |
| `board_test_sources (_app _out)` | extra source files (`.c`, `.S`, board glue, files outside the test directory) |
| `board_test_includes (_app _out)` | extra include directories |
| `board_test_linker (_app _out)` | another linker script for the hardware image |
| `board_test_options (_app _out)` | extra compile options for the test's own sources |
| `board_test_ncpu (_app _out)` | `OS_NCPU` for the test (default: the board's `UOS_BOARD_NCPU`) |
| `board_test_libs (_app _out)` | libraries to link |
| `BOARD_TEST_NEED_DEVICES` | tests that link the board device drivers |
| `BOARD_TEST_SELF_CONTAINED` | tests that must not get the shared `test/rpi-zero-2w/src/` |
| `BOARD_TEST_NO_KERNEL` | bare-metal tests, linked without the RTOS |

This board's `tests.cmake` already defines `board_test_defines()`, `board_test_libs()`: add a branch for your test **inside** the existing function. A hook that is not listed here can be added as a new function; the defaults return an empty list.

Example, a definition and an option for one test:

```cmake
function (board_test_defines _app _out)
  if (_app STREQUAL "smp-mat-test")
    set (${_out} MATRIX_SIZE=64 USE_FAST_PATH PARENT_SCOPE)
  else ()
    set (${_out} "" PARENT_SCOPE)
  endif ()
endfunction ()
```

### 3. Add a library

**A library of your own sources.** Keep it inside the workspace, declare it
once in `tests.cmake`, and return it from `board_test_libs()`:

```cmake
# micro-os-plus-iii-aarch64/test/rpi-zero-2w/tests.cmake
if (NOT TARGET mylib)
  add_library (mylib INTERFACE)
  target_sources (mylib INTERFACE
    "${CMAKE_CURRENT_LIST_DIR}/../../libs/mylib/src/mylib.cpp")
  target_include_directories (mylib INTERFACE
    "${CMAKE_CURRENT_LIST_DIR}/../../libs/mylib/include")
  target_compile_definitions (mylib INTERFACE MYLIB_STATIC)
endif ()

function (board_test_libs _app _out)
  if (_app STREQUAL "smp-mat-test")
    set (${_out} mylib PARENT_SCOPE)
  else ()
    set (${_out} "" PARENT_SCOPE)
  endif ()
endfunction ()
```

An INTERFACE library is compiled with the test's own flags (CPU, FPU,
`OS_NCPU`), which is what a bare-metal image needs. `micro-os-plus-iii-aarch64/libs/mylib/` is
only a suggested place; any path works.

**A pre-built archive.** Return its absolute path, and add its headers with
`board_test_includes()`. It must be built with the board's flags
(`-mcpu=cortex-a53`):

```cmake
set (${_out} "${CMAKE_CURRENT_LIST_DIR}/../../libs/vendor/libvendor.a" PARENT_SCOPE)
```

**An optional kernel component.** The kernel exports, besides
`micro-os-plus::iii`, the targets `micro-os-plus::iii-posix-io`, `micro-os-plus::iii-drivers`, `micro-os-plus::iii-startup`, `micro-os-plus::iii-newlib-reent`, `micro-os-plus::iii-semihosting`, `micro-os-plus::iii-trace-itm`, `micro-os-plus::iii-trace-semihosting`, `micro-os-plus::iii-trace-segger-rtt`. Return the one you need
from `board_test_libs()`; the test already links `micro-os-plus::aarch64`.

**A portable harness suite or an xPack.** The selected test uses none, so `tests/sources/` and the xPack libraries were not copied. To use one, copy `tests/sources/<suite>/` (and the xPack under `tests/xpacks/`) from the source harness, list the directory in `tests/platforms/aarch64-rpi-zero-2w/cmake/dependencies-folders.cmake` and return `test::<suite>` from `board_test_libs()`, or re-scaffold selecting a test that already uses it.

### 4. Add a new test

A test is a directory with at least one `.cpp` file; there is no test list to
edit.

```bash
cp -r micro-os-plus-iii-aarch64/test/rpi-zero-2w/smp-mat-test micro-os-plus-iii-aarch64/test/rpi-zero-2w/my-test
$EDITOR micro-os-plus-iii-aarch64/test/rpi-zero-2w/my-test/main.cpp
cd tests
./test.sh aarch64-rpi-zero-2w-cmake-gcc-debug my-test
```

- The executable is `my-test-<variant>` and the CTest case is
  `aarch64-rpi-zero-2w-my-test-<variant>`; both are created by the globs in
  `micro-os-plus-iii-aarch64/test/CMakeLists.txt` and `tests/platforms/aarch64-rpi-zero-2w/CMakeLists.txt`.
- This board has a QEMU linker script, so a test gets two variants, `qemu` and `hwd`. A test that needs the real hardware (SMP, UART, USB, timers) must be added to `BOARD_TEST_HWD_ONLY` in `tests.cmake`, otherwise its `qemu` image is built and run too.
- A copied test does not inherit the settings of the original: wherever
  `tests.cmake` names `smp-mat-test` (a list, or a branch of a hook: linker script,
  sources, libraries, CPU count), add `my-test` too if it needs the same.
- `./test.sh aarch64-rpi-zero-2w-cmake-gcc-debug --list` shows every registered case.
- To make the new test part of the default run (`./test.sh` with no test
  name), add one line to `tests/scripts/selected-tests.txt`; the three fields
  are separated by tabs:

  ```text
  aarch64-rpi-zero-2w-cmake-gcc-debug	my-test	aarch64-rpi-zero-2w-my-test-qemu,aarch64-rpi-zero-2w-my-test-hwd
  ```

- A test reports its verdict by printing `RESULT: PASS` or `RESULT: FAIL`;
  that line is what the runner looks for.

### 5. Kernel and port sources

The kernel is complete in `micro-os-plus-iii-smp/`. A new kernel or port source file is
not globbed; add it to the interface target:

```cmake
# micro-os-plus-iii-smp/CMakeLists.txt
target_sources (micro-os-plus-iii-interface INTERFACE src/rtos/os-new-feature.cpp)

# micro-os-plus-iii-aarch64/CMakeLists.txt
target_sources (micro-os-plus-iii-aarch64-interface INTERFACE src/new-port-file.cpp)
```

Headers go under the existing `include/` directories, which are already on the
interface include path.

### 6. Build and run scripts

| Script | What it does | When to edit |
| --- | --- | --- |
| `tests/scripts/env.sh` | tool paths and `PATH`, relative to the workspace | to change a tool, or export `UOS_TOOL_<NAME>` before calling the scripts |
| `tests/build.sh` | `cmake -S tests -B tests/build/<configuration> -G Ninja`, then the build | to pass another `-D` option to CMake (append to `CMAKE_ARGS`) |
| `tests/test.sh` | builds, then runs CTest for the named tests | normally never |
| `tests/scripts/selected-tests.txt` | the tests `./test.sh` runs by default | when a new test should run by default |
| `tests/platforms/aarch64-rpi-zero-2w/CMakeLists.txt` | registers the CTest cases and the command that runs each | to change the run command, its arguments or the timeout |
| `micro-os-plus-iii-aarch64/test/boards/rpi-zero-2w/hw.sh` | programs the board over OpenOCD and waits for the `RESULT:` line | to change the probe commands or the wait time |
| `micro-os-plus-iii-aarch64/test/boards/rpi-zero-2w/qemu.sh` | runs the QEMU images outside CTest | to change the machine arguments |
| `micro-os-plus-iii-smp/test_smpl/run-*.sh` | shared host/QEMU/hardware runners that parse the verdict and write the logs | normally never |

```bash
cd tests
./build.sh                      # configure and build
./build.sh --clean              # remove the build tree
./test.sh                       # build, run the selected test
./test.sh aarch64-rpi-zero-2w-cmake-gcc-debug my-test    # build, run one test by name
./test.sh --list                # the registered CTest cases
./test.sh smp-mat-test --hwd-only   # only the hardware case of one test
./test.sh --all --hwd               # everything that is registered
```

Hardware (`-hwd`) cases need the board and the probe. `./test.sh` skips them unless `--hwd` is given or the requested test has no other image. One board run is one CTest case; its log is under `tests/build/<configuration>/`.
